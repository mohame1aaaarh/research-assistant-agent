## 💡 فكرة المشروع

### المشكلة
الباحث والطالب بيضيع ساعات طويلة في البحث اليدوي عبر عشرات الأوراق البحثية، ومش قادر يحصل على إجابة سريعة وموثوقة مع مصدرها.

### الحل
نظام ذكاء اصطناعي يعمل كـ **مساعد بحث شخصي** — بيبحث في المصادر الأكاديمية، بيقرأ ملفات PDF، بيلخص الأوراق البحثية، وبيجاوب على أي سؤال مع ذكر المصدر تلقائياً — بالعربي والإنجليزي.

### اللي المشروع هيعمله

| الخاصية | الوصف |
|---|---|
| ✅ البحث الأكاديمي التلقائي | بيبحث في ArXiv و Semantic Scholar و DuckDuckGo |
| ✅ رفع PDF | بيقرأ أي ورقة بحثية ترفعها ويجاوب عليها |
| ✅ Citations أوتوماتيك | كل إجابة فيها مصدرها ومكانها بالظبط |
| ✅ تلخيص الأوراق | ملخص سريع لأي ورقة في ثواني |
| ✅ تاريخ المحادثات | بيحفظ كل أسئلتك وترجعلها أي وقت |
| ✅ عربي وإنجليزي | بيفهم ويرد بالاتنين |

### 1. 🎨 Chainlit — الواجهة

**بتعمل إيه:**
هي اللي المستخدم بيشوفها ويتعامل معاها. بتعمل Chat Interface شبه ChatGPT بالظبط، فيها عرض المصادر والـ Citations وتاريخ المحادثات — كل ده built-in من غير ما نكتبه.

**ليه اخترناها:**
لأنها مصممة أصلاً لـ AI Chat Apps، وبتتكتب بـ Python خالص، وشكلها احترافي من أول يوم.

**مثال بسيط:**
```python
import chainlit as cl

@cl.on_message
async def main(message: cl.Message):
    # لما المستخدم يبعت رسالة، هنا بنرد عليه
    await cl.Message(
        content=f"استلمت سؤالك: {message.content}"
    ).send()
```

### 2. 🧠 Agno — المخ والـ Agent

**بتعمل إيه:**
هو اللي بيقرر إزاي يرد على السؤال. بيحلل السؤال، بيقرر هيبحث فين، بيجمع النتائج، وبيبعتها لـ Gemini يلخصها. من غيره كنا هنكتب كل الخطوات دي بإيدينا.

**ليه اخترناها:**
أسهل framework موجود للـ AI Agents. الكود فيها واضح وقريب من Python العادي اللي إحنا عارفينه.

**مثال بسيط:**
```python
from agno.agent import Agent
from agno.models.google import Gemini
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    model=Gemini(id="gemini-2.0-flash-exp"),
    tools=[DuckDuckGoTools()],
    instructions="أنت مساعد بحث أكاديمي متخصص"
)

agent.print_response("إيه أحدث أبحاث الـ Neural Networks؟")
```

### 3. ✨ Gemini Flash — الذكاء الاصطناعي

**بتعمل إيه:**
هو اللي بيفهم اللغة فعلاً ويكتب الإجابات. Agno بيبعتله السؤال والمعلومات اللي جمعها، وGemini بيحولهم لإجابة مفهومة ومنظمة.

**ليه اخترناه:**
مجاني بـ Free Tier كافي جداً لمشروع كلية، وبيدعم العربي كويس، وأسرع من غيره.

**مثال بسيط:**
```python
import google.generativeai as genai

genai.configure(api_key="YOUR_API_KEY")
model = genai.GenerativeModel("gemini-2.0-flash-exp")

response = model.generate_content("لخصلي ورقة بحثية عن الـ AI")
print(response.text)
```

### 4. 🔍 ArXiv API — بحث الأوراق العلمية

**بتعمل إيه:**
بتدينا وصول مباشر لأكبر قاعدة أوراق بحثية في العالم — فيزياء، رياضيات، علوم حاسب، وأكتر. مجانية 100% ومن غير API Key.

**ليه اخترناها:**
متخصصة في الأبحاث العلمية بالظبط اللي مشروعنا محتاجه، ومجانية تماماً وبدون حدود.

**مثال بسيط:**
```python
import arxiv

client = arxiv.Client()
search = arxiv.Search(
    query="neural networks 2024",
    max_results=5
)

for paper in client.results(search):
    print(paper.title)
    print(paper.summary)
    print(paper.pdf_url)
```

### 5. 🌐 DuckDuckGo Search — البحث العام

**بتعمل إيه:**
بتدي الـ Agent قدرة يبحث في الإنترنت للأسئلة العامة اللي مش أكاديمية خالص. مجانية وما تحتاجش API Key خالص.

**ليه اخترناها:**
مجانية 100%، مفيش تسجيل، ومباشرة في Agno كـ built-in tool.

**مثال بسيط:**
```python
from agno.tools.duckduckgo import DuckDuckGoTools

# بيتضاف كـ tool للـ Agent مباشرة
tools = [DuckDuckGoTools()]
# الـ Agent هيستخدمه أوتوماتيك لما يحتاج يبحث
```

### 6. 📄 PDF Reader — قراءة الملفات

**بتعمل إيه:**
بتقرأ أي PDF يرفعه المستخدم، بتقطعه لأجزاء صغيرة، وبتبعتها للـ Agent يفهمها ويجاوب عليها.

**ليه اخترناها:**
Agno فيها PDF tool جاهزة built-in، ومش محتاجين نكتب كود إضافي.

**مثال بسيط:**
```python
from agno.agent import Agent
from agno.tools.file import FileTools

agent = Agent(
    tools=[FileTools()],
    instructions="اقرأ الملف وأجب على الأسئلة منه"
)

agent.print_response("لخصلي الملف ده", files=["paper.pdf"])
```

### 7. 🗄️ SQLite — الذاكرة

**بتعمل إيه:**
بتحفظ تاريخ المحادثات عشان لما المستخدم يرجع يلاقي كل أسئلته وإجاباته القديمة. مدمجة في Python من غير أي إعداد.

**ليه اخترناها:**
مدمجة في Python خالص — مش محتاجين نثبت أي حاجة، وكافية تماماً لمشروع كلية.

**مثال بسيط:**
```python
import sqlite3

conn = sqlite3.connect("conversations.db")
cursor = conn.cursor()

# حفظ محادثة
cursor.execute(
    "INSERT INTO history (question, answer) VALUES (?, ?)",
    ("إيه الـ AI؟", "الذكاء الاصطناعي هو...")
)
conn.commit()
```

## 🤔 إيه هو GitHub؟

تخيل إن الفريق بيكتب تقرير مع بعض على ورق. كل شخص بياخد نسخة، يكتب فيها، وبعدين بتحاولوا تجمعوا الكلام — الفوضى دي بالظبط اللي GitHub بيحلها.

**GitHub هو:**
```
✅ مكان واحد يتحفظ فيه كل الكود بتاع المشروع
✅ كل شخص يشتغل من غير ما يأثر على شغل التاني
✅ لو حصل غلط — تقدر ترجع لأي نسخة قديمة
✅ تتابع مين عمل إيه وإمتى
```

**المصطلحات الأساسية بالبساطة:**

| الكلمة | معناها |
|---|---|
| **Repository (Repo)** | المجلد الرئيسي للمشروع على الإنترنت |
| **Clone** | تنزيل نسخة من المشروع على جهازك |
| **Branch** | نسخة منفصلة تشتغل عليها من غير ما تأثر على الأصل |
| **Commit** | حفظ التغييرات اللي عملتها مع رسالة توضح إيه اللي اتغير |
| **Push** | رفع شغلك من جهازك لـ GitHub |
| **Pull** | جلب أحدث نسخة من GitHub لجهازك |
| **Pull Request (PR)** | طلب إضافة شغلك للمشروع الرئيسي |
| **Merge** | دمج شغلك في المشروع الرئيسي |

## 🔄 الروتين اليومي

> كل يوم قبل ما تبدأ تشتغل، لازم تعمل الخطوات دي بالترتيب.

---

### أول ما تفتح الجهاز — جيب أحدث نسخة

```
git pull origin main
```

ده بيجيب أي تغييرات عملها الفريق من بعد ما فتحت آخر مرة.

```
✅ Already up to date.    ← مفيش جديد، كل حاجة تمام
✅ Updating xxxx..xxxx    ← جه تحديثات جديدة اتنزلت
```

---

### لما تخلص شغل — احفظ وارفع

**الخطوة 1:** شوف إيه اللي اتغير
```
git status
```

هيطلعلك قائمة بالملفات اللي عدّلتها — المفروض تشوف اسم الملفات اللي شتغلت عليها.

**الخطوة 2:** ضيف التغييرات للحفظ
```
git add .
```
النقطة دي معناها "ضيف كل التغييرات."

**الخطوة 3:** احفظ مع رسالة توضح إيه اللي عملته
```
git commit -m "وصف قصير للتغيير"
```

أمثلة على رسائل كويسة:
```
git commit -m "أضفت دالة البحث في ArXiv"
git commit -m "صلحت مشكلة عرض النتائج بالعربي"
git commit -m "أضفت قراءة ملفات PDF"
```

أمثلة على رسائل وحشة — **متعملهاش:**
```
git commit -m "update"
git commit -m "fix"
git commit -m "aaaaaa"
```

**الخطوة 4:** ارفع شغلك على GitHub
```
git push origin اسم-الـ-branch-بتاعك
```

## 🌿 الـ Branches

> القاعدة الذهبية: **محدش بيشتغل على main مباشرة أبداً.**

---

### ليه بنستخدم Branches؟

```
بدون Branches:
كل الفريق بيكتب في نفس الملف
         ↓
شخص يكسر كود شخص تاني
         ↓
المشروع بيتعطل والكل يتأثر ❌

مع Branches:
كل شخص عنده نسخته المنفصلة
         ↓
يشتغل براحته من غير ما يأثر على حد
         ↓
لما يخلص يضيف شغله للمشروع ✅
```

---

### إزاي تعمل Branch جديد

**قبل ما تبدأ أي مهمة جديدة:**

```
git checkout -b feature/اسم-المهمة
```

أمثلة:
```
git checkout -b feature/pdf-reader
git checkout -b feature/search-tool
git checkout -b feature/chat-history
git checkout -b bugfix/arabic-display
```

**قاعدة تسمية الـ Branches:**
```
feature/اسم-الخاصية    ← لما بتضيف حاجة جديدة
bugfix/اسم-المشكلة     ← لما بتصلح مشكلة
```

---

### التنقل بين الـ Branches

شوف إنت على إنهي branch دلوقتي:
```
git branch
```
العلامة `*` قدام الاسم = ده اللي إنت عليه.

روح على branch تاني:
```
git checkout اسم-الـ-branch
```

روح على main:
```
git checkout main
```

## 📬 الـ Pull Request

> لما تخلص مهمتك وعاوز تضيف شغلك للمشروع الرئيسي.

---

### الخطوة 1 — ارفع الـ Branch بتاعك

```
git push origin feature/اسم-المهمة
```

---

### الخطوة 2 — افتح Pull Request على GitHub

روح على **github.com/mohame1aaaarh/research-assistant-agent**

هتلاقي رسالة صفرا بتقولك "Compare & pull request" — اضغط عليها.

لو مش لاقيها: اضغط على **"Pull requests"** ← **"New pull request."**

---

### الخطوة 3 — املى البيانات

```
العنوان:     وصف قصير لإيه اللي عملته
الوصف:       شرح أوضح للتفاصيل لو محتاج

مثال:
العنوان: "إضافة أداة البحث في ArXiv"
الوصف:  "بنيت دالة بتبحث في ArXiv وبترجع أول 5 نتائج
         مع العنوان والملخص والـ PDF link"
```

اضغط **"Create pull request."**

---

### الخطوة 4 — استنى الـ Review

Team Lead هيراجع شغلك ويعمل واحد من 3 حاجات:
```
✅ Approve + Merge    ← شغلك كويس واتضاف للمشروع
💬 Request Changes   ← في تعليقات محتاج تعدّل عليها
❌ Close             ← (نادر) في مشكلة كبيرة
```

## 🆘 مشاكل شائعة وحلولها

---

### المشكلة 1: "Your branch is behind"

```
error: Your branch is behind 'origin/main'
```

**المعنى:** في تحديثات على GitHub إنت مش عندكش.

**الحل:**
```
git pull origin main
```

---

### المشكلة 2: "Merge Conflict"

ده بيحصل لما شخصين عدّلوا نفس السطر في نفس الوقت.

**الحل:**
مش لازم تحله لوحدك — كلّم Team Lead على طول لأن ده ممكن يأثر على الكل.

---

### المشكلة 3: رفعت على main بالغلط

```
كلّم Team Lead فوراً من غير ما تعمل أي حاجة تانية.
```

---

### المشكلة 4: "fatal: not a git repository"

**المعنى:** إنت مش جوه مجلد المشروع.

**الحل:**
```
cd C:\Users\اسمك\Documents\research-assistant-agent
```

---

### المشكلة 5: نسيت على إنهي branch إنت

```
git branch
```
العلامة `*` هتوريك.

## 📏 القواعد الذهبية

```
1. ❌ ممنوع تكتب على main مباشرة أبداً
   ✅ دايماً اعمل branch جديد لكل مهمة

2. ❌ ممنوع commit من غير رسالة واضحة
   ✅ الرسالة تقول إيه اللي اتغير فعلاً

3. ❌ ممنوع تشتغل من غير ما تعمل pull الأول
   ✅ أول أمر كل يوم: git pull origin main

4. ❌ ممنوع تشتغل على ملفات مش بتاعتك من غير ما تقول
   ✅ لو محتاج تعدّل في ملف شخص تاني، كلّمه الأول

5. ❌ لو حصلت مشكلة مش فاهمها
   ✅ متعملش أي حاجة وكلّم Team Lead على طول
```

## 📱 الأوامر الأكتر استخداماً — خلي الورقة دي جنبك

```bash
# جيب أحدث نسخة (كل يوم أول حاجة)
git pull origin main

# شوف إيه اللي اتغير
git status

# اعمل branch جديد للمهمة
git checkout -b feature/اسم-المهمة

# روح على branch موجود
git checkout اسم-الـ-branch

# ضيف التغييرات
git add .

# احفظ مع رسالة
git commit -m "وصف التغيير"

# ارفع على GitHub
git push origin اسم-الـ-branch

# شوف إنت على إنهي branch
git branch
```
